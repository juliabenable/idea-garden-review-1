Affiliate Link Management & Distribution

Why this is cluster 06. The biggest gap creators name when comparing Benable to ShopMy. "I want to search past links, organize them, reuse them, share them where I already am." Morgan called this Benable's biggest product gap. Three pieces: (1) a real link library on the creator's side, (2) distribution surfaces (keyboard, native share, Instagram carousel, ManyChat), (3) click-level analytics so creators see what's working.

Critical: the keyboard (ID 25) and link gen (Nisarg, Apr 13) are deployed but the surrounding library and analytics are uneven. We're 60% of the way there.

Product doc · Link Library v1

Bundle IDs 39, 81, 26 into the surface power creators use most. Sets up everything else (analytics, distribution) to plug in.

The opportunity

Benable already generates affiliate links. What's missing is the place creators go to find a link they made last week, see what's getting clicks, and send it where they need it. ShopMy figured this out years ago. Closing the gap is table-stakes for retention of power creators.

v1 scope

  • Library view: all generated links, searchable by product name / brand / category. Default sort by recency, secondary by clicks.
  • Buckets: creator-defined folders (Spring '26, Skincare, Brand pitches) with drag-to-add.
  • Per-link analytics: clicks, click-through rate (if we know impressions), revenue (if affiliate network reports), trend sparkline.
  • Quick actions: tap-to-copy, share to Stories / Posts (uses cluster B distribution), pin to top.
  • Backed-by-keyboard: the iOS keyboard (ID 25) reads from this same library, so the keyboard "Recent" tab matches the web view.

Out of scope

  • Cross-creator analytics (showing creators what other creators link to). Defer.
  • Auto-categorization. Manual buckets first; auto in v1.5.
  • Per-link UTM tag editing. Power-user feature.

Open product decisions

D-12 · Should the link library be the home of the creator portal?
Option A · Yes — library IS the creator-portal home
Power creators live here. Aligns with the "creator-portal as monetization hub" thesis. Costs: pushes campaigns and lists to second-class navigation.
Option B · No — second tab next to "Campaigns" and "Lists"
Adds without disturbing existing IA. Lower disruption for non-power users. Recommended.
Option C · Built into each list page (no separate library)
Cleaner conceptually but doesn't match how creators think — they remember "the X link" more than "which list it's in."
D-13 · Where does revenue data come from for v1?
Option A · Show clicks only in v1; revenue in v1.5 once affiliate network integrations stabilize
Shippable now. Analytics is most-asked-for but revenue is hardest. Clicks alone is enough to start. Recommended.
Option B · Show revenue from AWIN + SkimLinks only; "—" elsewhere
More complete but inconsistent. Creators distrust holes.
Option C · Wait for Impact/CJ/Rakuten before launching analytics
Most complete. Slowest. Creators have been asking for ages.
