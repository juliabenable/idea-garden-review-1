Product doc · Idea maturation scorecard (ID 6)

A signal-strength meter on each idea. Forces the question: "Is this ready to scope, or do we need more evidence first?"

The problem this exercise just exposed

Going through 146 ideas to write Monday prep, the highest-friction question wasn't "is this a good idea?" It was "is there enough evidence behind this to commit a sprint?" The handoff doc has Granola sources, but no shape for "validation strength" or "blocker count." A scorecard is the missing layer.

Scorecard dimensions

  • Validation strength (0–3): 0 = idea-only · 1 = one data point or one interview · 2 = multiple sources or strong single signal · 3 = repeated independent confirmations
  • Effort estimate (XS / S / M / L / XL): rough; updated when scoped.
  • Dependency count (0–N): how many other ideas/projects have to ship first.
  • Open-decision count: how many product Qs are still open.
  • Last-touched age: green <30d, yellow 30–90, red 90+.

Maturation thresholds

  • Spark → Exploring: validation ≥1 OR explicit "let's poke at this."
  • Exploring → Has Legs: validation ≥2 AND open-decisions ≤3.
  • Has Legs → Ready to Scope: validation ≥2 AND open-decisions =0 AND effort estimated.

Thresholds are rules-of-thumb, not gates — you can always override. Their value is making "why aren't we shipping this?" answerable in one glance.
