Product doc · Pilot one community ("Communities v0")

Don't build "communities." Build one community with a real founder, validate the loop, then template it.

The opportunity

Sydny told us she runs a 75-day content challenge with ~12 micro-influencers. She'd run it on Benable if Benable could host it. She also said it'd net us ~12 warm creator leads. POTS communities work the same way: Sophia would actively bring people. Both stories show the same shape — someone with social capital + a small, real group + a recurring activity.

"Communities" as a generic feature has historically failed everywhere except Discord. Building a generic feature first is the trap. Hosting Sydny's actual group is the un-trap.

v0 scope (pilot, not feature launch)

  • One real community, owned by one real person. Either Sydny's PNW creator group or Sophia's POTS group. Stand it up manually with the host as co-designer.
  • Three primitives: a member roster, a recurring prompt (weekly question or daily check-in), and a shared list-collection that members contribute to.
  • Zero generalization. Hardcode where helpful. Goal is a repeatable pattern, not a feature.

Out of scope

  • Self-serve community creation. No "Create your community" button.
  • DMs, threads, video chat. Use existing channels (Slack/iMessage) for synchronous.
  • Feed algorithm. Just chronological.

Success criteria for pilot (60 days)

  • ≥70% of members return to the community page weekly.
  • Host says "yes I'd keep using this" without prompting.
  • ≥3 new creators sign up via this community alone (validates the warm-lead thesis).
  • Pattern is repeatable: we can describe in one paragraph how to start the next one.

Open product decisions

D-17 · Sydny's PNW creators or Sophia's POTS — which pilot first?
Option A · Sydny's PNW (creators)
~12 micro-influencers; brand-portal ready creators. Loop: warm leads for Benable + activity loop for them. Tighter to revenue. Recommended.
Option B · Sophia's POTS (consumers)
Validates niche-community thesis with consumers — shared experience around products. Less revenue-tight, more product-true. Equally good answer.
Option C · Both, in parallel
Most learnings; doubles the support burden in pilot. Probably wrong.
D-18 · Forum / tagging (ID 108) — pilot now or wait?
Option A · Build basic tagging into list discovery now
Lightweight social-discovery layer. Cassidy's "MySpace-chaotic but genuine" comment was real. Risk: tagging without participants is dead.
Option B · Wait for community pilot to inform tagging design
Tagging is more useful when there's already activity. Lets community pilot generate organic tag candidates. Recommended.
Option C · Drop forum/tagging entirely
Defensible if we commit to "Benable is not a forum." Don't lock that in until communities pilot tells us.
